Follow-ups App Explainer

Follow-ups App

Structure, building blocks, flow and features of the personal follow-up tracker. It has a phone app for capturing tasks, a desktop bulletin for reviewing them, and a Google Sheet as the record.

Purpose

DInstructions arrive all day by phone call, meeting, WhatsApp and letter, from the CMD, RCD Secretary, Chief Secretary, other officers, subordinates and the public. They concern SBPDCL, NBPDCL, the Energy Department, BSRDCL and RCD. The app captures each one in seconds, gives it a follow-up date, and keeps it in view until it is disposed.

Three Parts

Phone App

Add tasks (Paste & Save), see open follow-ups, tick them done, add notes, send on WhatsApp. It works even with no signal.

Desktop Bulletin

A newspaper-style page of open issues grouped as Overdue, Due today, This week and Later. It has Dispose, Edit, WhatsApp and Print.

Google Sheet

The permanent record. A small script attached to the sheet receives every change, writes it, logs it and makes a nightly backup copy.

DThe key design choice is save to the device first, send to the sheet later. You never wait for Google. If the network is slow or absent, the change simply waits on the phone and goes out when the signal returns.

Progressive Web App

BA Progressive Web App (PWA) is a normal website that the phone can install like an app, with a home-screen icon, a full screen with no address bar, and offline use. Two files make this possible: a manifest (the app's ID card) and a service worker (an offline helper).

Dmanifest.json gives the name "Follow-ups", the teal tick icon and "display": "standalone", which opens it without browser bars. That is why "Add to Home screen" turns the link into an app. Its share_target entry puts Follow-ups in the Android Share menu: a shared message opens index.html?text=….

Service Worker

BA service worker is a small script the browser keeps running in the background for one website. It can answer page requests itself, from a saved copy, instead of going to the internet.

Dsw.js uses a "cache first, refresh in background" rule. The page opens instantly from the saved copy while a fresh copy is fetched quietly for next time. It never touches calls to the Google server, so data is always live. It also ignores the extra part of a web address (for example the text of a shared message), so that text is never sent to GitHub or stored. Its cache has a version name (fu-v21). Changing that name makes phones throw away the old copy.

Local Storage

BlocalStorage is a small notebook (about 5 MB) that each website gets inside the browser. It holds text only, survives closing the app, and is private to that browser on that device.

DThe app keeps four entries:

KeyHolds
fu.tasksAll tasks (open, plus recently done), as JSON text
fu.queueThe waiting list of changes not yet confirmed by the sheet
fu.cfgServer link (/exec) and the key
fu.draftA half-typed task, restored if the app is closed by mistake

Sync Queue

DEvery change (add, done, +1 day, note, edit) becomes a small message called an operation, which is put on the waiting list. The app sends up to 50 at a time. Only the operations the server confirms are removed. If sending fails, it retries after 4 s, then 15 s, then every 60 s. The badge at the top shows the state: ✓ Synced or "2 waiting".

Web App Endpoint

BGoogle Apps Script can publish a script as a web app with a URL. Visiting the URL runs doGet, and sending data to it runs doPost. "Execute as: Me" means it writes to your sheet with your permission. "Anyone" means the phone can reach it without a Google sign-in. The secret key is what protects it.

JSON

BJSON is a plain-text way to write structured data, used between the app and the server. Example of one operation:

{ "op": "upd", "id": "Tm3k9x2ab", "f": { "status": "Done", "doneOn": "2026-11-08" }, "qid": "m3kb7q1zx" }

Inside index.html

DOne file holds three layers, top to bottom:

  1. <style>: the look. Colours are set once as variables (--ac:#0f8a7e teal), followed by rules for cards, chips, buttons and the list.
  2. HTML body: the parts of the screen, namely a header with a sync badge and tabs, then three sections: #v-add (form), #v-list (follow-ups) and #v-set (settings).
  3. <script>: the behaviour. Storage helpers, date helpers, chip selection, paste, save, list drawing, sync and pull.

Coding Blocks

The small building pieces the app is made of, each with a real example from its files.

HTML Element

BHTML describes what is on the screen. Each piece is an element in angle brackets; class links it to styles and data-… stores extra information for the script.

<button class="chip on" data-v="Energy">Energy Dept</button>

DThe class on marks it as already selected, which is how Energy Dept, CMD, 1 day and WhatsApp are the defaults.

CSS Rule

BCSS says how things look: a selector, then properties.

.chip.on{ background:var(--act); border-color:var(--ac); color:var(--ac2) }
.chip.on::before{ content:"✓ " }   /* adds the tick before a selected chip */

BA media query changes the layout by screen size. The bulletin uses columns:3 300px for newspaper columns, which fold to one column on a phone automatically.

Variable and Function

BA variable stores a value, and a function is a named recipe that can be reused. const means the value won't be replaced.

const DEF = {org:'Energy', from:'CMD', src:'WhatsApp', urg:''};   // default choices
const today = () => ymd(new Date());                          // "2026-11-08"

Event Listener

BThe script waits for something to happen, such as a tap, a key press or text being typed, and then runs code.

$('#saveBtn').onclick = addTask;           // tap Save → run addTask
document.addEventListener('keydown', e => {
  if ((e.ctrlKey || e.metaKey) && e.key === 'Enter') addTask();   // Ctrl+Enter
});

Object

BAn object groups named values together. Every task is one object:

{ id:'Tm3k9x2ab', text:'Bhagalpur Ganga Path, Buidco Pipeline issue',
  org:'BSRDCL', from:'Other officer – MD Buidco', name:'Animesh Parashar',
  source:'Call', due:'2026-11-09', urgent:'', status:'Open', remarks:'' }

Array Filter and Sort

BAn array is a list. filter keeps the items that pass a test, and sort puts them in order.

const overdue = open.filter(t => t.due < today());          // date earlier than today
overdue.sort((a,b) => a.due.localeCompare(b.due));          // oldest first

DDates are stored as YYYY-MM-DD text, so ordinary text comparison also gives the correct date order.

Template Literal

BBack-tick strings build text with values inside ${…}. The list and the bulletin are drawn this way:

`<span class="due">${dueLabel(t.due)}</span>`      // → "Tomorrow", "2 days late"…

DEvery value typed by a person passes through esc() first, which turns < into harmless text so a message can never break the page.

Local Storage Read and Write

const load  = (k,d) => JSON.parse(localStorage.getItem(k)) ?? d;   // read (simplified)
const store = (k,v) => localStorage.setItem(k, JSON.stringify(v));  // write

Async Fetch

Bfetch talks to a web address. async/await lets the code wait for the reply without freezing the screen.

const r = await fetch(cfg.u, { method:'POST',
  headers:{'Content-Type':'text/plain;charset=utf-8'},
  body: JSON.stringify({ k: cfg.k, ops: batch }) });
const j = await r.json();          // { ok:true }

DThe data is sent as text/plain on purpose. This is a "simple request" that Google's server accepts from any website without an extra permission check, which keeps saving to a single network call.

Apps Script Blocks

function doPost(e) {                                  // runs when the app sends data
  const b = JSON.parse(e.postData.contents);
  if (!keyOk(b.k)) return out({ok:false, error:'key'});
  const lock = LockService.getScriptLock();           // one writer at a time
  lock.tryLock(20000);
  try { applyOps(b.ops); } finally { lock.releaseLock(); }
  return out({ok:true});
}

Task Life Cycle

Open→Due / Overdue→ +1 day / +1 week →Open→Done→ untick →Open

DA task is never deleted by the app. "Dispose" only sets Status to Done and fills in Done on, so the full history stays in the sheet.

Flows

Add Flow

  1. Copy the WhatsApp message and open the app. It loads from the phone's saved copy in under a second.
  2. The defaults are already selected (Energy Dept, CMD, 1 day, WhatsApp). Change any if needed.
  3. Tap Paste & Save. The app reads the clipboard and spots a WhatsApp sender name ([08/11, 6:54 am] Name:).
  4. The app checks that the text is not empty and works out the follow-up date (today + 1 day).
  5. It builds the task object, adds it to fu.tasks, puts an add operation on the waiting list and shows "Saved · follow up Tomorrow".
  6. The form resets to the defaults, and sending starts in the background.

Share Flow

  1. In WhatsApp, long-press the message → Share → Follow-ups. This needs the app installed from Chrome with Install.
  2. The phone opens index.html?text=…. The app reads the text and removes it from the address at once.
  3. The task is saved with the defaults. A half-typed draft is put aside and brought back afterwards.
  4. The "Who sent it?" bar appears for 15 seconds, with CMD, RCD Secretary, Chief Secretary, your 6 recent names and Other…. One tap sets From, along with the office last used with that person.
  5. Sending waits while the bar is open, so the sheet gets the task with the right From in one entry. Undo removes it before it is ever sent.

BWhatsApp shares only the message text, not the sender's name or number. That is why the app asks "Who sent it?".

Sync Flow

  1. Take up to 50 waiting operations.
  2. Send them with the key to the /exec link.
  3. The server checks the key, locks, writes the Tasks rows and Log rows, then unlocks and replies {ok:true}.
  4. The app removes exactly the operations that were confirmed (matched by qid), and the badge turns to ✓ Synced.
  5. On failure, the operations stay on the phone and are retried automatically. They are also re-sent when the phone comes back online or the app is reopened.

Pull and Merge Flow

DOn opening, on returning to the app, and every 2 minutes on the bulletin, the app asks the server for the list (open tasks plus those done in the last 60 days) and merges it:

  • The sheet's version is taken as true, so edits made directly in the sheet appear in the app.
  • Except when a task has a change still waiting, or was changed on this device moments ago. Then the device's version is kept, so nothing you just did is undone.
  • Tasks deleted from the sheet disappear from the app at the next refresh.

Dispose Flow

  1. Tick the circle (phone) or click ✓ Dispose (bulletin).
  2. The item is struck through and fades out. Status becomes Done and Done on becomes today.
  3. An upd operation is queued and sent. Undo is offered for a few seconds.
  4. In the sheet, the row shows Done. Changing Status by hand in the sheet also fills Done on, through the sheet's onEdit rule.

WhatsApp Flow

DCopy or WhatsApp builds this text:

Bhagalpur Ganga Path, Buidco Pipeline issue
Ref: MD Buidco

Please complete the pipeline shifting by 15 Nov and share the status.

The Ref is the name part of From ("Other officer – MD Buidco" gives "MD Buidco", and CMD gives "CMD"). The note follows after one blank line. The WhatsApp button opens wa.me with this text. If the Name field holds a 10-digit mobile number, the link opens that person's chat directly.

Data Safety


    

  • DKey check: requests without the right key are refused.
    • 

  • DScript lock: two devices saving at the same second cannot overwrite each other.
    • 

  • DNo duplicates: a resent task with the same ID is ignored.
    • 

  • DText kept as typed: a leading apostrophe stops "8/11 call" from turning into a date, keeps the leading 0 of a phone number, and makes "=…" plain text, never a formula.
    • 

  • DLog tab: every change is recorded, and only the owner can edit it.
    • 

  • DIndia time: follow-up dates never shift by a day.

Maintenance


Change Default Choices

In index.html, find const DEF= and change the values, for example org:'SBPDCL'. In the HTML, move the word on to the same chips so the first screen matches.


Add an Office or From Option

In index.html, copy a chip line such as <button class="chip" data-v="RCD">RCD</button>, then change the data-v value and the label. For offices, also add the name to the STD list in both index.html and bulletin.html.


Publish a Page Change

Upload the changed files to GitHub. Also open sw.js and raise the version (fu-v21 → fu-v22) so phones pick up the new copy. Reopen the app once or twice.


Publish a Server Change

Paste the new Code.gs into Apps Script and save. Then Deploy → Manage deployments → ✏ → Version: New version → Deploy. The link stays the same.


Restore from Backup

Open Drive → "Follow-ups backups", open the copy you need, and copy the rows back into the Tasks tab. A phone's own copy can also be saved with ⚙ → Download backup (JSON).


Add Another Person

For a separate list: they make their own sheet with Code.gs and open your app address with their own #u=…&k=…. For a shared list: give them your setup link.

Glossary




Apps Script
Google's JavaScript that runs on Google servers and can work with Sheets, Drive and Gmail.


Batch
Several changes sent together in one call.


Cache
A saved copy kept for fast reuse.


Clipboard
Where copied text sits until it is pasted.


Deployment
A published version of the Apps Script web app, with its own /exec link.


Endpoint
A web address that a program sends data to.


Event
Something that happens on the page (tap, typing, key press) and that code can react to.


Fetch
The browser command to send or receive data over the internet.


GitHub Pages
Free hosting that publishes files in a GitHub repository as a website.


JSON
A text format for structured data, such as {"status":"Done"}.


Local Storage
A small private store inside the browser for each website.


Lock
Lets only one save write to the sheet at a time.


Manifest
The file that makes a website installable as an app.


Merge
Combining the sheet's list with the device's list without losing recent changes.


Operation
One recorded change, either add or upd.


PWA
Progressive Web App: a website that installs and works like an app.


Queue
The waiting list of changes not yet confirmed by the sheet.


Service Worker
A background script that serves the app from the device for instant and offline use.


Sync
Sending waiting changes and fetching the latest list.
